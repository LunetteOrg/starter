Compare the change with the project's decision records (ADRs, product decisions,
process descriptions), listed below.

1. **Read the records now**, each one's index and its sections. Build every check from
   what they say today, never from memory.
2. **Violations:** a change that contradicts an accepted record is a blocker; drift or
   a partial application a warning. Cite the record by file and heading anchor.
3. **Unrecorded decisions:** a choice visible in the change (a new capability, a new
   convention, a changed contract) that no record covers is a note naming the log it
   belongs in.
4. **Records out of shape**, among those the change touches: a numbered or
   superseded-by record, a struck-through amendment, a process rule inside an ADR, a
   configuration value copied instead of cited by its key, a document that narrates how
   it was reached instead of the state it proposes.
